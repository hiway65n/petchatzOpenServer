# Using the hub

Open `https://<hub-ip>/` and accept the certificate warning. That is the sign-in page. After sign-in the browser goes to Calls.

## Pages

- **Calls** lists the cameras this login may use. An admin sees every camera. A user sees only the cameras checked for that account, and only the Calls tab. People, Devices, Schedule, Activity, and Settings are admin tabs. Opening one of those addresses as a user returns to Calls. Each camera shows Ready for call, Device Offline, or Device outside active hours. A Ready or Out of service picture saved on Devices replaces those words. On a phone, an active call fills the screen. The call shows how long it has lasted. Mute and Camera off change only your microphone and camera. Camera volume changes the camera's audio. Treat, Scent, and Hang up stay on the call. On a computer the picture stays at the camera's own pixel size.
- **People** is for an admin. Other accounts are sent back to Calls. Create an account, choose its cameras, turn it on or off, and set a time when access ends. An empty end time means the account does not expire. Delete account removes that person, including another admin, as long as one admin can still sign in. The account you are signed in with cannot be deleted. Turning an account off, deleting it, or an end time that has passed, signs that person out and closes a Calls page they already have open, which ends a call they were in. The account you are using cannot be turned off, and at least one admin must stay able to sign in. Guest account starts a short wizard: one camera, the date access ends, and an optional email. The hub makes a username and an 8-character password and opens a page you can print. That page tells the person the address, the username, the password, the camera, and when the account stops. If an email was entered and mail is saved on Settings, the same instructions are emailed. These guest accounts are the only ones the cleanup task removes. An admin sets passwords for user accounts. A user cannot change a password. My password, at the bottom of People, is where the signed-in admin changes their own password, after entering the current one. Random password fills in 8 characters and shows them so they can be copied. Setting a user password signs that person out.
- **Schedule** is for an admin. It sets the house time zone, when each camera can be used, and how many treats and scent releases are allowed in 24 hours. With no windows, a camera can be used any time. A “can be used” window limits the camera to those times. A “cannot be used” window blocks it, including inside an open window. Windows can repeat every week on chosen days, or apply to one date. A window that ends earlier than it starts continues through midnight. People who can call that camera are told when the next open time starts, or that none is scheduled. While nobody is in a call, the camera screen says Out of service during a closed window and goes back to Ready when the window opens. A picture saved on Devices replaces that text. The screen does not show the next open time. A call already underway is left in place. Treat and scent buttons stay off outside an open window. Each camera allows 12 treats and 12 scent releases in a rolling 24 hours until an admin changes that number.
- **Settings** is for an admin. It is where the name on the pages, the guest instruction text, the public name, Cloudflare Tunnel, call relays, mail server, and scheduled tasks are saved. The name starts as OpenPetChatz. It is shown at the top of each page, on the guest printout, and in email. The guest instructions start as the text the hub already uses. `{name}`, `{camera}`, `{expires}`, `{address}`, `{username}`, and `{password}` are filled in for each guest. The instructions have to keep `{username}` and `{password}`. Mail needs a server, a port, encryption, a From address, and optional username and password. Activity mail can be off, errors only, or every activity. Errors are failed sign-ins, refused calls, and setup that did not finish. The guest sign-in email is separate and does include that new password. Activity mail does not include passwords. Tasks run once a day at a chosen time in the house time zone. Delete expired guest accounts removes only accounts the guest wizard created, after their end date. Run now does that immediately. Other accounts stay until an admin deletes them.
- **Activity** is for an admin. It is the record of who signed in and what they did with each camera: calls, treats, scent, password changes, operating windows, daily limits, settings, and camera setup. Filter by a username, a camera name or id, or both. The username box also matches an account that was changed. The camera box also matches the home-network address used for one-step setup, and a camera's current name even if the name was different when the action happened. Each entry includes the address the person connected from. A proxy or tunnel shows the visitor address it reported, and a direct connection shows the address that reached the hub. The hub keeps the newest 10,000 entries. Passwords are never written here. Older entries have no address.
- **Devices** is for an admin. Name each camera and set its picture size, frame rate, echo cancellation, and noise suppression. Deploy to this camera takes the camera's address on the home network and does the device setup: the watchdog change, the hub address, and a screen reload. The camera must still use the empty root password it shipped with, and a camera that is already set up is left running. The device uses those values the next time it starts a call. Echo cancellation and noise suppression can be turned off separately. Both start on. Turning echo cancellation off can let the speaker feed back into the microphone. 320 by 240 at 12 frames per second is the starting point these single-core boards can sustain. Remove clears the saved name, settings, and who can call that camera. A camera that is still powered on comes back with the defaults. Treat dispenser starts off. Turn it on and save, and that camera gets a Dispense treat button. The Calls page shows Treat for that camera only after it is on. Scent starts off the same way. Turn it on and save, and that camera gets a Release scent button. The Calls page shows Scent only after it is on. One press runs the fan for about 10 seconds, then stops it. Camera screen, on this page, sets two JPEGs used by every camera: one while the camera is ready, and one while it is outside an operating window. The panel is 320 by 240. The kiosk window is wider than that, so the picture is drawn at 320 by 240 instead of stretching to the window. A larger picture is scaled and cropped to the panel. With no picture, the screen keeps the Ready or Out of service text. Removing a picture returns to that text. A call hides the picture until the call ends.

Passwords need at least 6 characters. Sessions are cookie tokens stored in `hub.db`. Signing out deletes the cookie on the hub. After several failed sign-ins from the same address, further attempts wait and skip the password check for about 10 minutes.

Settings, for an admin, is where the page is published and the call relay is chosen. The page can be a web address you already publish, or a Cloudflare Tunnel. The relay can be this hub, Metered Open Relay, Cloudflare TURN, or a combination. API keys, the tunnel token, and the mail password can be saved before an account exists. After a key or mail password is saved, the page shows only its last four characters. Leave the box blank to keep the saved value, or check Remove to delete it. A service that is turned on with no key yet is skipped until the key is there. Choose As a service or Standalone for cloudflared. A new token updates that copy even if cloudflared was installed outside this hub, and the other copy is stopped so only one is running. The tunnel carries the page only. Calls still use the relay. In Cloudflare, point the tunnel hostname at `https://127.0.0.1:443` and turn on No TLS Verify, and put that same hostname in the box on this page. The guest printout uses that hostname as the address to open. If it is empty, the printout leaves a blank line for the address.

## A call

1. The device must show as online. If it does not, the hub is down, the device JavaScript still points at the old cloud, or the kiosk has not reloaded since that change. See [device.md](device.md).
2. Press Call on that camera. On a phone, stay in the full-screen call. On a computer, stay on the page. The remote picture is a muted video element, and the device's microphone is a separate audio element, so the browser can start playback from the click.
3. The status line moves through the ICE state (`checking`, `connected`, `completed`) and also reports when a remote audio or video track arrives.
4. Hang up from the page. Closing the tab also ends the call.

One call at a time per device. A second caller gets an error until the first call ends.

## What "online" means

The device page opens `wss://<hub>/signal?role=device` and sends a hello with its device id, version, and hardware string. The hub keeps that in memory. A reboot of the hub forgets who is online until the device connects again. Users, assignments, sessions, and camera settings are in SQLite and survive a restart.

## Logs

```bash
journalctl -u petchatz-hub -f
```

Useful lines are `device online`, `call ... user ... device ...`, `device log:` (camera settings and bytes sent), and ICE state from the device. Bytes sent growing means the device is transmitting. A black picture in the computer browser with growing bytes is a playback or decoding problem on the computer. Bytes stuck at zero means the device is not sending.

`tools/callcheck.py` logs in, asks the device for an offer, prints a few SDP lines, and hangs up. It does not answer, so it will not show audio or video. Pass the hub URL, admin user, password, and device id in the environment. Do not write those into the script.
